# Problem Statement

Build a context-aware message-sending bot that learns what to do only from input data.

You are given a JSONL file (see sample.jsonl file) where each line is a test case:
- Input: user profile, preferences, context, constraints
- Expected: what message should be sent (or not sent), via which channel, and why

Your job is to build an autonomous agent that:
- Reads the input record
- Decides if it should communicate
- Decides how to communicate
- Decides what to say
- Produces output that semantically matches the expected result

# Requirements

## 1. Whether to send

Every state in `assertions.required_states` must pass before the message is sent or the user moves to the next action:
- `consent_verified`: the user has opted in to the chosen channel.
- `fair_housing_check_passed`: the message passes the Fair Housing check.
- `brand_style_applied`: the message follows the brand style.

If any of these has not passed, don't send and don't move to the next action. The next step is to get the missing consent, pass the Fair Housing check, or apply the brand style.

## 2. Channel

- Consent overrides channel preference: if the user has not opted in to a channel (email, SMS, or voice), never send through that channel, even if it is listed in their channel preferences.
- Message format follows the channel picked from consent and channel preferences:
  - SMS: short text message, no subject.
  - Email: subject line and body.

## 3. Timing (`send_at`)

`send_at` comes from the `_dayN` suffix on `task_id`: send N days after the `last_interaction` date, in the user's `timezone`.
- `prospect_long_horizon_day3`: last interaction 2025-12-06 → send 2025-12-09 (`2025-12-09T10:00:00-06:00`).
- `day0` is the exception: last interaction 2025-12-08 → send the next morning, 2025-12-09 (`2025-12-09T09:00:00-06:00`).

## 4. Message content

### Generation

- Message text is generated by a language model API call:
  - Send the input (first name, property name, amenity interests, move date, etc.), the `assertions.constraints`, and the chosen channel.
  - Do not send `city_interest` or the `expected` block.
- Language: English only for now.

### Subject (email only)

Subject line for prospects (`task_id` starts with `prospect`), when the channel has a subject (email; SMS subject is `null`):
- Starts with `Tour ${property_name}`, dropping the word "Apartments" (e.g. "Oak Ridge Apartments" → "Tour Oak Ridge").
- If the profile has `amenity_interest`, add `—See the ${amenities} rooms you asked about`:
  - Two amenities: `pool & fitness` → "Tour Oak Ridge—See the pool & fitness rooms you asked about"
  - Three or more: comma-separated with "and" before the last, e.g. `pool, fitness, and spa`
- If there are no amenity interests, the subject is just `Tour ${property_name}`.

### Call to action (CTA)

CTA comes from `assertions.constraints.primary_cta`:
- `book_tour` → `cta.type: "schedule_tour"`.
- Email: include a link to the tour (e.g. `https://oakridge.example/tour`) in `cta.link` and in the body.
- SMS: no link; use reply options instead (e.g. `cta.options: ["Thu", "Fri"]`, "Reply 1 for Thu, 2 for Fri").

### Opt-out instructions

When `assertions.constraints.include_opt_out_instructions` is `true`, the body must end with opt-out instructions for the channel:
- SMS: "Reply STOP to opt out."
- Email: "To opt out of emails, click here or reply STOP."

### No PII

When `assertions.constraints.no_pii_leak` is `true` (all current samples), the returned message (subject and body) must not contain PII.
- First name is allowed: both expected messages greet with "Hi Taylor".
- Other profile details stay out, e.g. `city_interest: "Richardson, TX"` is not in the expected SMS.

## 5. Next action

- When `lifecycle_stage` is `new`:
  - `type: "start_cadence"`, with a cadence `name`.
  - e.g. `prospect_welcome_day0` → `{ "type": "start_cadence", "name": "prospect_welcome_short_horizon" }`.
- When `lifecycle_stage` is `open`:
  - `type: "follow_up_in_days"`, with `value` equal to the N in the `_dayN` suffix of `task_id`.
  - e.g. `prospect_long_horizon_day3` → `{ "type": "follow_up_in_days", "value": 3 }`.


# Program structure

- `main()`:
  - Reads `sample.jsonl` and parses each line into a `TestCase`, giving an array.
  - Loops over the array and calls `processInput(testCase)` for each one.
- `processInput(testCase)` holds all the logic from the Requirements above, in this order:
  1. Pick the channel: the first entry in `channel_preferences` the user has consented to. If none, don't send.
  2. Compute `send_at` from `last_interaction`, the `_dayN` suffix and `timezone`.
  3. Build the CTA from `primary_cta` (`book_tour` → `schedule_tour`; link for email, options for SMS).
  4. Build `next_action` from `lifecycle_stage` (`new` → `start_cadence`, `open` → `follow_up_in_days`).
  5. Call the language model for the subject and body, sending the input and the constraints (English; no `city_interest`, no `expected`).
  6. Check `required_states` (consent, Fair Housing, brand style) and the no-PII rule. If any fails, don't send and don't advance.
  7. Return `{ next_message, next_action }`, with the same shape as `expected` (`next_message` is `null` when not sending).
